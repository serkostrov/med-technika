## Вердикт по текущему состоянию

Проект — чистый каркас **Vite + React 19 + TypeScript**. Доменного кода, Supabase, Tailwind/shadcn, парсера и миграций нет. ТЗ v1.0 (04.10.2026) — единственный источник требований; ниже — план, совместимый с ним.

**Принципы (жёстко из ТЗ):**
- RLS везде; права только через `is_head()` / `is_engineer()` / `current_staff_id()`.
- Смена `status` — только RPC §14; прямой `update status` запрещён.
- Аудит — триггеры, не фронт.
- Парсер/XML/проверки — сервер; фронт скрывает кнопки, но не является границей безопасности.

## 4. Жизненный цикл протокола

```
[upload+save] → review
      │
      │ protocol_approve (head; нет active error; все active warning ack)
      ▼
   approved
      │
      │ auto: scan PDF + application_date заполнены
      ▼
    ready ──► exported (включён в build-fgis-xml)
                  │
                  ▼
                sent (export_mark_uploaded)
```

| Переход | Кто / как |
|---|---|
| → `review` | загрузка; любая правка §6.8 в `approved`/`ready`; `protocol_return` |
| → `approved` | только `protocol_approve` |
| → `ready` | автоматически при `approved` + скан + `application_date` |
| → `exported` | `build-fgis-xml` |
| → `sent` | `export_mark_uploaded` |
| soft-delete | до `exported`; после — запрет |

Повторный выбор `exported` в пакет — разрешён (предупреждение). После выгрузки replace файла по номеру+дате — запрет (ФЛК 5).

## 5. Источник истины / запреты / откат / роли / серверные проверки

### Источник истины
- **Измерения, FactValue, U, шапка из Excel** — исходный `.xlsx` (сохранённые значения + `number_format`); пересчёт на сервере только для W02, **в XML всегда FactValue из протокола**.
- **ОА, EquipmentId, idFullName, единицы** — справочники ФГИС/клиента.
- **Текст методики/показателя в XML** — из ОА, не из протокола.
- **Статус и журнал** — БД (RPC + триггеры).
- **Передача во ФГИС** — ручная отметка (API ФГИС вне scope).

### Нельзя редактировать в системе
- Сырые замеры, среднее Excel, U Excel, FactValue, номер/дата из файла, условия из файла и т.п. — только новый Excel + replace.
- Исходный файл в Storage — immutable.
- Enum-значения — только расширять.

### Правки, разрешённые в карточке (§6.8)
`application_date`, `accred_scope_353`, даты измерений для 26-ИДК; привязки customer/equipment/staff/oa; `include_in_xml` с комментарием.

### Автовозврат в `review`
Любая правка через `protocol_update` / смена сопоставлений / include в статусе **`approved` или `ready`** → сброс утверждения, `status = review`. (После `exported`/`sent` замена файла запрещена; правка доменных полей, ведущая к повторной выгрузке, должна оставаться совместимой с ТЗ — фактически выгрузка уже свершилась; повторный export возможен для `exported`.)

### Начальник ИЛ
Загрузка; все протоколы; правки §6.8; ack; approve/return; скан; XML + mark uploaded; delete до export; CRUD/import справочников; пользователи/настройки; весь журнал.

### Инженер
Загрузка; только свои (`uploaded_by` или `engineer_staff_id`); правки/ack/скан/delete(review) по своим; чтение справочников; создание заказчика при загрузке; журнал по своим. **Нет:** approve, return, XML, mark uploaded, правка справочников (кроме customer create), пользователи/настройки.

### Обязательно серверные
- RLS и все смены статуса.
- `parse-protocol`, FactValue, пересчёт uA/uB/U.
- `protocol_run_checks` (после save/update и при изменении справочников для review/approved/ready).
- `protocol_approve` / `return` / `attach_scan` / `delete` / `build-fgis-xml` / `export_mark_uploaded`.
- XSD-валидация; лимит 100; дедуп SHA-256; unique (number, date).
- Аудит-триггеры.

Клиент: предпросмотр импорта справочников (SheetJS), UX, скрытие кнопок.

## 6. Все места `[УТОЧНИТЬ]` и безопасная архитектура

Правило: **конфиг/данные/профиль**, не hardcoded ветки в ядре. Гипотеза из ТЗ — default; смена — seed/settings/форма без переписывания пайплайна.

| # | Место | Гипотеза ТЗ | Безопасная точка расширения |
|---|---|---|---|
| 1 | Суффиксы номера (РК, ЭД, МК…) §6.2 | по имени шаблона | `measurement_kinds.suffix` + таблица/поле `protocol_forms.number_suffix_rules` |
| 2 | Даты измерений 26-ИДК §6.3 | ручной ввод | флаг в `protocol_forms.settings.manual_measure_dates` |
| 3 | Якорь «Протокол оформил» отсутствует §6.3 | поиск по профилю | `parser_profile` + optional `engineer_locator` в settings формы |
| 4 | FactValue: суффиксы/% в number_format §6.6 | уточнить | стратегия форматтера в `packages/fact-value` + таблица тест-кейсов |
| 5 | Лимит размера пакетного XML §10.1 | без лимита + warning | `settings.max_export_file_bytes` (null = без лимита) |
| 6 | `AccredScope353` в XML §10.2 | выводить только если true | XML emitter: feature flag `emit_accred_scope_353` |
| 7 | TypeObjectId для произв./окруж. среды §10.2 | справочник DM-52863 | `protocol_forms.type_object_id` (уже в модели) |
| 8 | Directory для не-продукции §10.2 | вероятно DM-53535 | `protocol_forms.fgis_directory` |
| 9 | DocNameId vs UniqueMethod при id методики §10.2 | гипотеза DocNameId | `settings.xml_method_emit_mode` = `doc_name_id` \| `unique_method` \| `auto` |
| 10 | Conditions в XML §10.2 | нет в эталонах физ.; уточнить | `protocol_forms.settings.emit_conditions` + маппинг на DM-54873 |
| 11 | Листы «Дети_», «Прил. МУК…» — форма или приложение §19 | не решать в коде ядра | `form_status` / отдельная форма vs `settings.ignore_sheets` |
| 12 | W01: error или warning §19 | сейчас warning | `settings.severity_overrides` (`{"W01":"error"}`) — уже в DDL |
| 13 | Заказчики ИП/ФЛ §19 | kind 2/4 | `customers.kind_id` + условная валидация в E13/E14 |
| 14 | Профили без BB:BE — что в FactValue §6.4 | только по эталонному XML | форма остаётся `no_materials`/`in_progress` до XML; профиль не в `ready` |
| 15 | uB для НЧ и прочих 26-МТ §6.5 | снять из BH | `form_indicator_map.ub` per indicator |

Открытые вопросы §19 ведёт Сергей; разработчик не пишет клиенту.
